# 技术架构与旧路线取舍

## 推荐架构

本版本将“发音是什么”和“这段声音发生在何时”分开求解：CMUdict/MFA G2P 负责候选音素，Montreal Forced Aligner 负责真实音频时间，项目代码只负责教学分组、拼写映射、安全切片和界面同步。

| 模块 | 职责 | 失败策略 |
|---|---|---|
| `core/phonology.py` | CMUdict、ARPAbet 标准化、学习型 IPA、最大声母分组 | 不猜未知发音 |
| `core/mfa.py` | MFA G2P、`align_one`、TextGrid 读取、候选发音核验 | 序列不一致即拒绝分段 |
| `core/grapheme_alignment.py` | 已知音素与拼写之间的加权多对多单调对齐 | 高成本或跨组映射即拒绝 |
| `core/audio.py` | 单次完整词合成、PCM 解码、低能量切点、淡入淡出、教学音轨 | 无合法时间范围即拒绝切片 |
| `core/pipeline.py` | 串联任务、版本化缓存、完整词降级 | MFA 缺失时只保留完整词 |
| `ui/playback.py` | 由 `QAudioSink.processedUSecs()` 驱动高亮 | 播放中断立即清除高亮 |
| `ui/main_window.py` | 后台生成、last-wins 结果、响应式教学卡片 | 旧请求完成后不覆盖新结果 |

## 自动分段算法

1. 在已确认的音素序列中定位元音核。
2. 把相邻元音间允许作为英语声母的最长辅音簇分给下一组，其余保留在上一组。
3. 使用动态规划对齐拼写和已知音素。转移来自常见单字母、二合字母和多字母拼写单元，例如 `th↔TH`、`tion↔SH AH N`、`one↔W AH N`；未知转移有很高代价。
4. 将拼写边界投影到音素组边界。若一个不可拆的拼写单元跨越两个发音组，或总代价超过阈值，不生成误导性结果。
5. 少量经过人工核对的教学显示修正存于 `data/alignment_overrides.json`，必须同时完整覆盖拼写和实际音素序列；它不是按单词写死的播放逻辑。

## 音频切片

切点只能位于相邻发音组之间。程序以 MFA 标注边界为中心，在严格的 ±3 ms 窗口内寻找兼顾低短时能量、过零点和最小位移的采样点；每个导出片段加入 5 ms 淡入淡出。这能降低波形截断造成的爆音，同时避免为了寻找远处静音而吞掉相邻辅音。完整词只裁去对齐范围以外的长静音，不改变词内波形。

## 与旧 TTS 路线的差异

旧项目中“完整词 TTS”这一能力可以保留，但职责收窄为单一基础音源。以下思路不能继续作为核心：

- 按音素数量或字符串长度把完整词时长等比例分配；
- 用 Pyphen/连字符直接决定真实发音组；
- 为 `every`、`one` 等字符串分别调用 TTS 后拼接；
- 用媒体播放器的粗粒度 seek 事件猜高亮时间。

本项目位于新的工作目录，没有修改或删除旧项目。缓存也使用 v2 指纹，防止旧的估算时间数据混入。

## 仍需承认的限制

- TTS 的重音或同形异音选择未必符合用户想表达的词义；声学对齐只能确认“录音实际说了哪个候选”。
- 极少见姓名、借词和高度不规则拼写可能被严格模式拒绝，需要在核对录音与词典后补充映射规则。
- 单词级孤立录音没有句子中的连读和弱化；它适合词汇教学，不等价于连续语流训练。
